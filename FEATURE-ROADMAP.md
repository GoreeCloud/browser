This file is the repository-side feature roadmap control for GoreeCloud Browser. It records current planned and recommended feature work without replacing the authoritative repository `SPECIFICATIONS.md`, verified repository implementation evidence, release gates, or GoreeCloud Tasks Management.

## Current Development checkpoint

PR #49 remains open Development/beta work on `chatgpt/search-index-browser-2026-09-13`. The native-extension source line now includes the manifest/package-inventory and permission-ledger foundations, the bounded GCEX v1 package-byte reader and strict native manifest decoder, the corrected fail-closed package-trust boundary, Browser-owned durable permission-ledger snapshot/recovery, and the first bounded GCEX cryptographic signature-verification layer. `docs/GCEX_PACKAGE_FORMAT_V1.md` records the byte-level package contract, `docs/EXTENSION_PERMISSION_LEDGER_STORAGE_V1.md` records the permission-persistence contract, `docs/GCEX_SIGNATURE_V1.md` v0.2 records the signature contract, and `docs/NATIVE_EXTENSION_PLATFORM.md` remains the broader supporting architecture.

GCEX reader implementation source `80c577eb6533349bdb5212a145efc6080663d358` is verified by Platform Contract #66, GoreeCloud Browser Android Beta APK #244, and GoreeCloud Browser Core CI #485. Permission-ledger persistence implementation source `2026b06ddfd5353bf5c021bb1a6938e734313f15` is independently verified by Platform Contract #72, GoreeCloud Browser Android Beta APK #250, and GoreeCloud Browser Core CI #491. GCEX signature implementation source `756e3683ed145f00b3d04b7f27f488c77b5fac9d` is independently verified by Platform Contract #88, GoreeCloud Browser Core CI #507, GoreeCloud Browser Android Beta APK #266, and dedicated GoreeCloud Browser Extension Signature #6. Later documentation commits do not inherit or strengthen implementation-source validation by implication.

The signature milestone uses a GoreeCloud-owned adapter over exact libsodium 1.0.22 source commit `77e1ce5d6dee871c49ef211222ba18ef0c486bda`, with ISC license/provenance recorded under `third_party/`. The dedicated lane builds that exact dependency and runs the standalone CMake verification harness with assertions enabled. A valid `ed25519-sha256-v1` package-local signature can promote only `unsigned_package` to `signed_package`; it cannot establish developer identity or `verified_signature`. Ordinary Browser builds and runtimes do not acquire signature enforcement from this milestone, and no installer, extension execution runtime, trusted developer-key authority, production signing, or production trust decision is claimed.

The permission-persistence source serializes only active same-profile `always` grants and still-valid `one_hour` grants. Volatile `once`, tab, website, and browser-session lifetimes are not serialized; one-hour recovery preserves the original deadline; profile mismatch and clock regression fail closed; bounded snapshots use CRC32 for accidental-corruption detection; first-run absence restores an empty ledger; and a previous valid snapshot can be used as an explicit backup after primary corruption. CRC32 is not cryptographic authenticity, and the current helper does not claim production-grade power-loss durability, authenticated-at-rest state, multi-process coordination, runtime integration, or production acceptance.

The authoritative Browser specification is repository Markdown `SPECIFICATIONS.md` v0.11 under current Markdown-first GoreeCloud documentation governance. The legacy Drive project-specification DOCX remains only a superseded migration record. Sections 16–18 define proposed implementation contracts for permission/private-context handling, Wardveil-gated downloads, and tabs/sessions/profiles/Webspaces runtime state. `docs/BROWSER_SYNC_PHASE_0.md` v0.1 elaborates `SPECIFICATIONS.md` §11 into an implementation-ready Browser Sync Phase 0 contract aligned to the verified shared `GoreeCloud/goreecloud-sync` dataset registry, record envelope, acceptance, replay, tombstone/receipt, and bounded retrieval foundations. `docs/NATIVE_EXTENSION_PLATFORM.md` v0.2 defines the GoreeCloud-native extension runtime direction, `.gcex` packaging, manifest/API/permission model, decentralized installation and updates, isolation, transparency, Glaze UI surfaces, developer tooling, storage, enterprise policy, and production-acceptance direction without relying on an external extension ecosystem or centralized store.

The Browser authority model continues to evaluate exactly seven Integral Platform Systems: GoreeCloud Manager, Privacy Shield, Wardveil Security, Everkeep, GLAZE UI, GoreeCloud Mesh, and GoreeCloud Identity. GoreeCloud Search, GoreeCloud Index, GoreeCloud Sync, Vault, DNS, Network, Bookmarks, Webspaces, and other first-party products/services remain separately governed capability or authority relationships.

## Next bounded implementation sequence

1. Introduce isolated extension-runtime/process boundaries with privileged Browser API dispatch disabled by default and no execution authority derived merely from package parsing, signing, or installation state.
2. Define the independent trusted developer-key / organization trust authority required for `verified_signature`, including enrollment, rotation, revocation, compromise response, and explicit user/organization policy without a mandatory centralized store.
3. Continue declarative APIs, controlled Glaze UI surfaces, transparency/firewall/resource controls, decentralized updates/rollback, developer tooling, and production acceptance as independently verified milestones.
4. Keep production/Release Candidate/Stable claims gated on independent runtime, security/privacy, accessibility, resource, device, update/recovery, dependency/vulnerability, and release evidence.
