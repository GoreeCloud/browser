## Purpose

This file is the repository-side feature roadmap control for GoreeCloud Browser. It records current planned and recommended feature work without replacing the authoritative repository `SPECIFICATIONS.md`, verified repository implementation evidence, release gates, or GoreeCloud Tasks Management.

## Current Development checkpoint

PR #49 remains open Development/beta work on `chatgpt/search-index-browser-2026-09-13`. The latest independently verified implementation checkpoint remains exact source `f62e650a0fdb7a85fb5c7cd997bed7750a3ba82f`, which passed Platform Contract #34, GoreeCloud Browser Core CI #451, and Android Beta APK #212. Sections 16–18 define proposed implementation contracts for permission/private-context handling, Wardveil-gated downloads, and tabs/sessions/profiles/Webspaces runtime state. `docs/BROWSER_SYNC_PHASE_0.md` v0.1 now elaborates `SPECIFICATIONS.md` §11 into an implementation-ready Browser Sync Phase 0 contract aligned to the verified shared `GoreeCloud/goreecloud-sync` dataset registry, record envelope, acceptance, replay, tombstone/receipt, and bounded retrieval foundations. The Browser authority model continues to evaluate exactly seven Integral Platform Systems: GoreeCloud Manager, Privacy Shield, Wardveil Security, Everkeep, GLAZE UI, GoreeCloud Mesh, and GoreeCloud Identity. GoreeCloud Search, GoreeCloud Index, GoreeCloud Sync, Vault, DNS, Network, Bookmarks, Webspaces, and other first-party products/services remain separately governed capability or authority relationships.

## Current sequencing recommendation

1. Establish accepted GoreeCloud Identity requester authentication for Browser → Search and the corresponding Search → Privacy Shield direct-service authentication path.
2. Implement runtime Privacy Shield decision/capability acquisition and only then connect bounded Search discovery/POST transport after Search proves required server-side enforcement and authenticated requester resolution.
3. Implement the Browser-owned permission broker, privacy-context state model, Android runtime-permission mapping, ephemeral private decisions, and fail-closed request lifecycle from Sections 13 and 16.
4. Implement the quarantine-first Wardveil download pipeline, authenticated object-bound verification, atomic release, private-context semantics, and restart/retry safety from Sections 14 and 17.
5. Complete GLAZE UI V1.4.1 rendered/native accessibility, localization/RTL, large-text, reduced-effects, representative-device, and performance acceptance.
6. Implement Browser Sync Phase 0 from `docs/BROWSER_SYNC_PHASE_0.md`: consume the canonical `browser.tabs`, `browser.history`, and `browser.preferences` capability contracts; define Browser payload schemas; add the durable outbound journal; implement projection/apply pipelines; preserve separate `bookmarks.*` authority; integrate shared acceptance/replay/tombstone/receipt/retrieval primitives; and pass the Phase 0 acceptance matrix while Private/Isolated Private remains excluded.
7. Build the native GoreeCloud Vault credential adapter and UX only against explicit versioned Vault capabilities, preserving Vault as the sole credential authority and keeping Private/Isolated Private behavior fail closed.
8. Implement the Browser-owned tabs/sessions/profiles/Webspaces foundations from Sections 15 and 18: stable logical object identities, deterministic lifecycle state, Normal-session journal/checkpoints, process-death restoration, profile/Webspace isolation, engine recreation, resource management, and explicit Sync/Everkeep boundaries.
9. Progress remaining Everkeep/other service integrations, desktop engine acceptance, production signing/provenance, recovery/rollback, Release Candidate, production, and Stable gates only as independent evidence becomes available.
